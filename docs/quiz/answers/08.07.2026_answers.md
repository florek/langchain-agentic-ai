## Uzasadnienia

**1. B** — Agentic AI to podejście, w którym model nie tylko generuje tekst, lecz podejmuje decyzje i wykonuje działania w pętli obserwacja → rozumowanie → akcja, korzystając z narzędzi zewnętrznych.

**2. D** — Projekt wymaga Pythona w wersji co najmniej 3.12, przypiętej w konfiguracji środowiska.

**3. A** — `load_dotenv()` wczytuje zmienne z pliku `.env` do środowiska procesu i domyślnie nie nadpisuje zmiennych już ustawionych w systemie operacyjnym.

**4. C** — RAG (Retrieval-Augmented Generation) służy do odpowiadania na podstawie własnej, aktualnej dokumentacji poprzez dołączenie pobranych fragmentów do promptu.

**5. B** — Chat Models operują na listach wiadomości (SystemMessage, HumanMessage, AIMessage), podczas gdy klasyczne LLM przyjmują i zwracają surowe stringi.

**6. D** — Plik `.env` jest ignorowany przez Git, aby zapobiec przypadkowemu commitowaniu kluczy API i innych sekretów do repozytorium.

**7. A** — LangGraph modeluje przepływy jako grafy stanów z warunkowymi przejściami, checkpointami i wsparciem dla systemów multi-agentowych — więcej kontroli niż prosta pętla agenta.

**8. C** — Few-shot prompting jest szczególnie skuteczny przy zadaniach wymagających określonego formatu odpowiedzi, takich jak klasyfikacja tekstu lub ekstrakcja strukturalna (JSON).

**9. A** — W materiale kursu wymienione są trzy bazy wektorowe: FAISS (lokalna), Chroma (lekka, na prototypy) i Pinecone (zarządzana usługa chmurowa).

**10. B** — W tool calling model zwraca strukturalne żądanie wywołania funkcji, runtime wykonuje narzędzie i przekazuje wynik (observation) z powrotem do modelu w kolejnej iteracji.

**11. D** — uv zapewnia szybką instalację zależności, deterministyczny plik lock z dokładnymi wersjami i automatyczne tworzenie środowiska wirtualnego.

**12. C** — Pułapka „lost in the middle" oznacza, że modele gorzej wykorzystują informacje umieszczone w środku długiego kontekstu — kluczowe dane warto umieszczać na początku lub końcu.

**13. B** — LangSmith służy do śledzenia (tracing), debugowania i ewaluacji wywołań łańcuchów i agentów LangChain.

**14. A** — Wzorzec ReAct przeplata Thought (rozumowanie), Action (wywołanie narzędzia) i Observation (wynik narzędzia wstawiany przez runtime).

**15. D** — LCEL (LangChain Expression Language) to deklaratywne składanie komponentów łańcucha operatorem `|`, np. `prompt | model | output_parser`.

**16. C** — ConversationSummaryMemory kompresuje historię rozmowy do podsumowania, w przeciwieństwie do ConversationBufferMemory, która przechowuje pełną historię.

**17. B** — MCP (Model Context Protocol) to standardowy protokół łączenia LLM z zewnętrznymi źródłami kontekstu i narzędziami w ujednoliconym formacie.

**18. A** — Rozmiar chunków i strategia podziału wpływają na jakość dopasowania dokumentów do zapytania bardziej niż sam wybór modelu generującego odpowiedź.

**19. D** — System multi-agentowy sprawdza się przy bardzo złożonych zadaniach wymagających wyspecjalizowanych ról — np. planowania, wyszukiwania i raportowania — gdzie pojedynczy agent jest ograniczony.

**20. C** — Natywne tool calling jest preferowane, bo generuje mniej halucynacji formatu i zapewnia lepszą niezawodność strukturalnych wywołań niż tekstowy format ReAct.
