### 7. [LangChain] — brak odpowiedzi

**Pytanie:** Który element NIE jest przykładem możliwego kroku w łańcuchu LangChain?

**Twoja odpowiedź:** brak | **Poprawna:** D

Krok łańcucha w LangChain może być wywołaniem LLM, promptem, transformacją danych, tool call lub zagnieżdżonym łańcuchem. Kompilacja modelu do bytecode JVM nie ma nic wspólnego z ekosystemem LangChain — to element dystraktora mający na celu wyeliminowanie oczywistych odpowiedzi. Zasada projektowa: łańcuch to kompozycja komponentów LangChain, gdzie wynik jednego kroku staje się wejściem następnego.

### 10. [Prompt Engineering] — brak odpowiedzi

**Pytanie:** Który element NIE należy do składowych skutecznego promptu opisanych w materiale?

**Twoja odpowiedź:** brak | **Poprawna:** D

Skuteczny prompt składa się z roli systemowej, kontekstu zadania, ograniczeń, przykładów few-shot i danych wejściowych użytkownika. Pełna historia commitów z repozytorium Git nie jest elementem prompt engineeringu — to dystraktor sugerujący, że wszystko związane z kodem trafia do promptu. Zasada: prompt zawiera tylko to, co model potrzebuje do wykonania zadania, nie metadane projektu.

### 12. [Agentic AI] — błędna odpowiedź

**Pytanie:** Czym jest pamięć długoterminowa w systemach agentowych?

**Twoja odpowiedź:** A | **Poprawna:** B

Pamięć długoterminowa to trwałe przechowywanie faktów o użytkowniku lub sesji (np. w bazie danych lub wektorowej). Odpowiedź A opisuje pamięć krótkoterminową — historię bieżącej konwersacji w oknie kontekstowym, która znika po zakończeniu sesji lub gdy zostanie skompresowana. Pułapka polega na myleniu tych dwóch poziomów: krótkoterminowa mieści się w kontekście modelu, długoterminowa przetrwa między sesjami.

### 13. [Konfiguracja] — brak odpowiedzi

**Pytanie:** Co zwraca `os.getenv("OPEN_AI_KEY")`, gdy zmienna środowiskowa nie została ustawiona?

**Twoja odpowiedź:** brak | **Poprawna:** A

`os.getenv()` zwraca `None`, gdy zmienna nie istnieje — nie rzuca wyjątku `KeyError` (to robi `os.environ["KEY"]`) i nie zwraca pustego stringa. Aplikacja powinna obsłużyć ten przypadek (komunikat błędu lub fallback) zanim spróbuje wywołać API. Zasada bezpieczeństwa: klucze API trzymamy w zmiennych środowiskowych, a kod musi gracefully obsłużyć ich brak.

### 16. [Context Engineering] — brak odpowiedzi

**Pytanie:** Na czym polega strategia pruning tool results?

**Twoja odpowiedź:** brak | **Poprawna:** C

Pruning tool results polega na obcinaniu zbyt długich wyników narzędzi przed dołączeniem ich do kontekstu (np. tylko pierwsze 500 znaków odpowiedzi API). Wyniki narzędzi mogą być bardzo obszerne i szybko wyczerpać okno tokenów — pruning to świadoma decyzja context engineeringowa, nie usuwanie wszystkich wyników (A) ani przenoszenie chunków RAG (D). Każda iteracja agenta dokłada dane do kontekstu, więc kontrola rozmiaru wyników narzędzi jest kluczowa.
